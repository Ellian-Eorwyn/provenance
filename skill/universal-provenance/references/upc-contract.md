# UPC Output Contract (skill-local, 1.8.0)

The condensed, self-sufficient contract for producing a conformant Universal
Provenance Corpus. The full normative spec is in `spec/` at the standard's root;
this is what a producing tool needs at write time. Where this and the spec
disagree, the spec governs.

## Codes and codings (since 1.6.0)

A **codebook** is the scheme; a **coding** is one judgement recorded against one
object. Both live under their own `sections` keys, and `loadCorpus` reads them
only if `corpus.json` declares those keys — there is no directory sniffing.

- `codebooks/<cbk-id>.json` — `cbk-` is hashed over `(namespace, slug)` **only**,
  so a codebook's codes can be edited freely without re-minting anything or
  dangling an existing coding. `revision` and `revision_digest` carry evolution
  and are advisory. `codes[]` needs at least one entry, even when `closed: false`.
- `codings/<set-id>/{manifest.json, items.jsonl}` — the manifest declares
  `coders[]` (`coder`, `kind: model|human|ensemble|adjudicator`, and the volatile
  model/prompt detail), so a model upgrade does not destroy agreement history.
- A coding **never carries a locator**. Its `target` is an `extraction`, `source`
  or `representation`, so a span-level coding points at something that already
  passed the gate. A code can never become a second, ungated way to point at text.
- `cod-` is hashed over `(codebook_ref, target, coder, code|value)`. Re-running an
  unchanged pass writes nothing; a *changed* answer from the same coder supersedes
  the old one; two coders disagreeing produce two retained records, and no surface
  may pick a winner.

Produce them in two steps, never one: `upc anchor` decides which proposed spans
are real, then `upc code` records judgements against the spans that survived.
`upc add source` writes sources; `upc export --format site` publishes the result.

## Layout (default; `corpus.json.sections` is authoritative)

```text
<corpus>/
  corpus.json                          # root manifest (required)
  sources.csv  extractions.csv         # projections (regenerated by `upc regen`)
  sources/<slug>/
    source.json                        # per-source manifest
    representations/…                  # raw.html, clean.md, images/, media/, transcripts/
    extractions.jsonl                  # per-source extractions
    generated/<gen-id>.json (+ <gen-id>.md, rating.json)
  extractions/<set>/{manifest.json, items.jsonl}   # optional query sets
  syntheses/<syn-id>/{synthesis.json, synthesis.md}
  provenance/events.jsonl              # activity journal (L2)
  index.html                           # generated browser (projection)
  .upc/                                # tool-private; never a member
```

Writers emit the per-source layout; readers honor whatever `sections` declares
(a per-media-type layout is a permitted readable variant — Appendix A).

## Objects & required fields

- **corpus.json** — `upc_spec_version`, `corpus_id`, `sections`. Self-describing
  (`readme`, `rules_note`). Machine-owned; regenerate with `upc regen`, never
  hand-edit. `counts`/index arrays are advisory.
- **source.json** — `source_id` (`src-<12hex>`), `source_kind`, ≥1
  `representations[]`. Add `bibliographic` (CSL), `retrieval`, `aliases`,
  `field_evidence`.
- **representation** — `representation_id` (`rep-`/`img-<12hex>` = the file's byte
  hash), `role`, `media_type`, `path` (corpus-relative, inside root, portable),
  `sha256` (over the exact stored bytes). Tool-produced text is UTF-8, LF,
  soft-wrapped.
- **extraction** — `extraction_id` (`ext-<12hex>`), `source_id`,
  `representation_ref`, `type`, `locator`, and at least one of `text`/
  `direct_quote`. **A `direct_quote` MUST equal the representation's codepoints at
  a `char_range` locator, byte-for-byte** (hop-B gate). `status` defaults to
  `active`; only active quotes are gated.
- **generation** — `generation_id` (`gen-<12hex>`), `type`, `provenance`; inputs
  in `provenance.derived_from`; `provenance.input_digest` for staleness;
  `output.sha256` for a file output.
- **synthesis** — `synthesis_id` (`syn-<12hex>`), `type`, `provenance`; `claims[]`
  each citing `evidence_ids`/`source_ids`; the rendered output cites every id its
  claims use and marks each quotation `"…" [ext-id]` (hop-C gate).

## Quotation gates (the core guarantee)

`output quote  ==exact==  extraction.direct_quote  ==exact==  representation bytes at locator`

No normalization at verification time. Hop A: representation bytes hash to
`sha256`. Hop B: `codepoints(utf8_decode(bytes))[start:end] === direct_quote`.
Hop C: every `"…" [ext-id]` in output equals that extraction's `direct_quote`.
Site-only link markers — `[theme:<codebook>/<code>]`, `[view:<name>]` — are
navigation, not citations: never checked, never counted, and never placed
directly after a quotation (that would stop it being one).
Copy quotes with `upc quote`; check output with `upc verify-quotes`. To quote
less, `upc quote <id> --narrow <a> <b>` (mints a sub-quote). A coarse locator
(page/section) can never carry a gated quote — put such context in
`secondary_locators`.

## Identity (spec §06, recomputed by the validator)

`<prefix>-<first 12 hex of sha256(UTF-8 key)>`. JSON in a key uses JCS (RFC 8785).

- **src** key = `"src\n" + canonical_url` (closed URL normalization) or
  `"src\nsha256:" + <64hex of primary bytes>`.
- **rep/img** = first 12 hex of the file's byte sha256 (no key string).
- **ext** key = `"ext\n" + source_id + "\n" + representation_ref + "\n" +
  JCS(locator) + "\n" + (direct_quote else text)`.
- **gen** key = `"gen\n" + type + "\n" + JCS(sorted input ids) + "\n" +
  input_digest`; **syn** key = `"syn\n" + type + "\n" + question + "\n" +
  JCS(sorted input ids)`.

Keep your tool's own id in `aliases { "<tool>": "<id>" }`. `upc mint <kind>`
computes an id from a JSON object on stdin.

## Provenance stamp (on every derived object)

```json
"provenance": {
  "produced_by": { "tool": "…", "tool_version": "…", "model": "…", "method": "…", "prompt_version": "…", "person": null },
  "created_at": "ISO-8601Z",
  "modified_at": null,
  "derived_from": { "source_ids": [], "representation_refs": [], "extraction_ids": [], "generation_ids": [], "synthesis_ids": [] },
  "input_digest": "sha256:…"
}
```

`model`/`prompt_version` only when a model produced it; `method` from the
`produced_by_method` vocab; `person` for a human edit. Sources carry `retrieval`
instead of `derived_from`. `input_digest` lives here only (single input = its byte
hash; multi-input = the JCS manifest hash, spec §07).

## Closed vocabularies (`vocab/vocab.json`)

`interpretation` explicit|inferred|unclear · `confidence` high|medium|low
(+ numeric `confidence_score`) · `extraction_status` active|needs_review|
superseded|retracted · `status` success|needs_review|failed|skipped ·
`activity_type` incl. modify|reanchor|retract|remove|redact ·
`representation.role`, `extraction.type`, `locator.type`, `generation.type`,
`synthesis.type`, `produced_by_method` per vocab. Extensible types use an `x-`
prefix (reported as `x_extension`, a warning).

## Locator shapes (by `locator.type`)

`char_range`/`line_range` → `{start,end}` (ints) · `page` → int ≥1 · `heading`/
`section`/`css_selector`/`xpath`/`url` → string · `timestamp_range` →
`{start,end}` sec · `bbox` → `[x,y,w,h]`. Every locator's `representation_ref`
equals the extraction's. Only `char_range` (Unicode codepoints, 0-based,
end-exclusive) is gate-bearing.

## Conformance & durability

- **L0** corpus + sources + ≥1 hashed representation each; paths contained
  (realpath); portable filenames; well-formed JSONL.
- **L1** + ids recomputed & unique + references resolve + typed locators + **every
  active `direct_quote` passes hop B** + provenance stamps + CSL bibliographic.
  L1 guarantees no unverified quotations in the corpus.
- **L2** + generations/syntheses with `derived_from` + `input_digest` + hashed
  outputs + **hop-C output gate** + `events.jsonl` journal.

Writes are atomic (temp + rename). JSONL: UTF-8, LF, one object/line, trailing LF;
a torn final line is a warning, an interior bad line an error; `events.jsonl` is
append-only. Removal is journaled (retract/remove/redact) then `regen`.

`node scripts/upc.mjs validate <corpus>` implements the §08 registry exactly and
prints findings keyed by error code (e.g. `quote_gate_failed`, `rep_hash_mismatch`,
`output_quote_mismatch`, `id_mismatch`, `locator_rep_mismatch`,
`claim_missing_source`, `uncited_in_output`, `path_escape`, `symlink_escape`).
Warnings (advisory, `--strict` promotes some): `stale_input`, `csv_stale`,
`counts_mismatch`, `unknown_field`, `flagged_extraction`, `cites_superseded`,
`output_quote_uncited`, `x_extension`, `confidence_inconsistent`,
`alias_collision`, `jsonl_torn_tail`. The full table is spec/08.
